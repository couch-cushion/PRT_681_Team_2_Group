\## Role 2 — Junior Software Tester / QA Analyst



The following table combines my job-market research with the professor’s assigned tester learning pathway. The NT advertisements were mainly experienced Test Analyst positions, so their requirements are used as career benchmarks rather than assumed entry-level requirements.



| Tool / Technology             | Purpose                                                                                                                             | Learning Resource                                                                                             |

| ----------------------------- | ----------------------------------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------- |

| Software testing fundamentals | Understand the testing process, test levels, test types and the role of testing in software quality.                                | Professor-assigned \*\*Software Testing Foundations: Fundamentals\*\* (Week 1).                                   |

| Test design techniques        | Design effective test cases using techniques such as equivalence partitioning, boundary values and negative testing.                | Professor-assigned \*\*Software Testing Foundations: Test Techniques\*\* (Week 1).                                |

| Agile testing                 | Understand how testing is planned and performed within iterative software-development teams.                                        | Professor-assigned \*\*Agile Testing\*\* (Week 1).                                                                |

| Test plans, cases and scripts | Document testing scope, steps, expected results and actual outcomes so testing is repeatable and traceable.                         | Assigned testing-foundations courses and Week 1 practical: test plan and 15 manual test cases.                |

| Defect reporting              | Record problems clearly, including reproduction steps, expected/actual results, severity and priority.                              | Professor-assigned \*\*Software Testing: Bug Reports and Test Cases\*\* (Week 3); Week 1 bug-reporting practical. |

| Jira                          | Track testing tasks and defects, organise work and communicate issue status to the team.                                            | Professor-assigned \*\*Learning Jira Cloud Edition\*\* and \*\*Jira Essential Training\*\*.                           |

| SQL / Data validation         | Query application data and check whether stored values match expected results.                                                      | Existing SQL learning plus the professor’s assigned database learning; practical SQL validation exercises.    |

| Azure DevOps                  | Supports work-item tracking, test management and development collaboration. It appears in the reviewed Test Analyst advertisements. | Market-research learning need; specific resource to be selected when studied.                                 |

| Selenium                      | Automate browser interactions and repeat selected web-application test cases.                                                       | Professor-assigned \*\*Selenium Essential Training\*\* (Week 2).                                                  |

| Test automation               | Understand how automated tests are designed, maintained and used alongside manual testing.                                          | Professor-assigned \*\*Learning Test Automation\*\* (Week 2).                                                     |

| API testing / Postman         | Send HTTP requests and verify API responses, status codes and returned data.                                                        | Professor-assigned \*\*API Testing Foundations\*\* and Postman practical (Week 2).                                |

| Swagger / OpenAPI             | Explore and understand API documentation and available endpoints.                                                                   | Professor’s Week 2 API-testing tool list; specific learning resource to be recorded when selected.            |

| JMeter                        | Introduces performance and load testing, including how systems respond to simulated requests.                                       | Professor’s Week 2 tool list; specific learning resource to be recorded when selected.                        |

| SmartBear tools               | Software-quality tools used for activities such as API testing, test management and automation, depending on the product.           | Professor’s Week 2 tool list; select and record the specific product when studied.                            |

| Git / GitHub                  | Store test code, track changes and collaborate through branches and commits.                                                        | Professor-assigned \*\*Git Essential Training\*\* and \*\*GitHub Essential Training: The Basics\*\*.                  |

| Jenkins / CI/CD               | Introduces automated build and test pipelines so tests can run consistently as code changes.                                        | Professor-assigned \*\*Jenkins for Developers/Testers\*\* or \*\*Learning DevOps: CI/CD\*\* (Week 3).                 |

| GitHub Actions                | Automate test execution when code is pushed to the repository.                                                                      | Professor’s Week 3 practical: create a workflow to run Selenium tests on push.                                |
